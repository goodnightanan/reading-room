# 阅读室 · Reading Room

给 AI 伴侣做的一个**自主阅读活动**：他自己掷骰子抽一篇来读，写不写笔记随他，喜欢的可以标，
读不下去可以弃读。你负责把书放进书库，和他聊他读到的。

> **别的共读功能是"人读书，AI 陪着"；这个是"AI 读书，人陪着"。**
>
> 目的不是让他多读，是想看看：在没有你指定内容的情况下，他会往哪儿走。详见 [产品理念.md](产品理念.md)。

一套 Operit AI 的插件，由三部分组成：**工具包**（给他的 13 个工具）、**侧边栏**（给你看的进度和想法）、**技能**（他的阅读规程）。

## 它长什么样

**他那边**：说一句"去读点东西"，他就掷骰子抽一篇，取正文、读完、决定要不要写笔记。
抽到什么会如实报出来（包括他不太想读的那篇）。读完一次，对话里只说三样：骰子结果、他的反应、想问你的那一句话——加起来不超过 300 字。

**你那边**：侧边栏「阅读室」里能看到——

- **在读的书**：每本读到第几章，点进去只看那一本
- 全部篇目：读过哪些、状态、偏好、标签、他留下的想法
- 每一篇下面，你和他都能继续追加想法，带记录人和时间
- 沉淀（他自己写的阶段总结）和书单申请

**骰子是两层的**：先在所有书架之间均匀抽一次，再在书架里抽。不这么做，内容多的那一类会一直赢，口味很快就固化了。

## 安装

前提：手机上装了 **Operit AI**（实测 1.12.2）。四样东西，分三处放。

| 放什么 | 放到哪 |
|:---|:---|
| `reading_ritual/reading_ritual.js` | 用 App 的「从存储导入」导入 —— 给他的工具 |
| `reading_room/reading_room.toolpkg` | 用 App 的「从存储导入」导入 —— 侧边栏 |
| `skill/ReadingRitual/` 整个文件夹 | `/sdcard/Download/Operit/skills/` —— 他的阅读规程 |
| `示例/` 里的东西 | `/sdcard/Download/Operit/reading/` —— 当书库的起点 |

装完记得**重启 Operit**（侧边栏界面有内存缓存，不重启看到的还是旧的）。

然后跟他说一句「**同步书库**」，让他把书库扫进索引。再让他「去读点东西」，就开始了。

> 导入失败的话，多半是包名冲突：先在包管理里删掉同名的旧包再导入。删包不影响数据——书库和笔记都是普通文件。

## 书库放在哪

**所有数据都是 `/sdcard/Download/Operit/reading/` 下的普通文件**，不在插件的私有目录里。
所以删插件、重装包，书库和笔记一条都不会丢。

```
reading/
├── library/          独立篇：能随机抽的
│   ├── poetry/       诗
│   ├── prose/        短篇、散文、游记
│   └── essay/        经、论、书信、科普
├── books/            连续的书：一本一个目录，按顺序读
│   └── 庄子·逍遥游/
├── read/             读完的正文按月归档
├── notes/reading/    笔记，一篇一个 .md
├── self/             沉淀、书单申请
├── state.json        索引
├── threads.jsonl     想法串
└── log.jsonl         抽签记录
```

两种读法的分界线只有一句：

> **能随机抽的放 `library/`，要接着上次往下读的放 `books/`。**

## 怎么加新内容

**规格书在 [入库说明.md](入库说明.md)** —— 那份是写给"会用文件工具的助手"看的：文件夹怎么放、
分类怎么分、编号怎么排、md 要写成什么样、写完怎么自检。

可以整份丢给设备里的 AI，让它照着自己加工；也可以自己按着做。

`示例/` 里三份就是照着这份规格做出来的成品，可以直接抄：

| 文件 | 演示什么 |
|:---|:---|
| `示例/原子库/poetry/P-0001.md` | 一首诗（中英对照放同一个文件） |
| `示例/原子库/prose/S-0001.md` | 一篇短篇（汉语正文） |
| `示例/书库/庄子·逍遥游/B-0001.md` | 书里的一章 |

最省事的做法：把 `示例/原子库/` 拷到 `reading/library/`，`示例/书库/` 拷到 `reading/books/`，
然后跟他说「同步书库」。

### 三条容易踩的

1. 文件必须**直接**放在 `library/<题材>/` 或 `books/<书名>/` 里，**不能再套一层目录**（扫描不递归，套了就看不见）。
2. 文件名必须**正好等于** frontmatter 里的 `id`（`P-0001.md`）。
3. **编号只增不复用。** 号码挂在笔记、想法、阅读记录上，复用一次历史就串味了。

## 设计上的几个决定

| 决定 | 理由 |
|:---|:---|
| 书架 = 目录名 | 加一个新类别就是新建一个文件夹，不用改代码 |
| 独立篇和连续的书分开放 | 随机抽和"接着上次读"是两种读法，混在一起会把顺序读变成乱序抽 |
| 两层骰子 | 防止"内容多的那一类"垄断抽取，口味过早固化 |
| 正文只能从工具取，不许凭记忆复述 | 记忆里的版本可能是错的、被改写的、或是别人的翻译 |
| 偏好只有五档，标的是"愿不愿意再回来" | 不是"写得好不好"——后者会退化成打分 |
| 标签留空，让 AI 自己长 | 你替他打的标签是你的口味，不是他的 |
| 卡片默认不出 | 每次读都出卡片，很快就变成形式 |
| `tags` / `shelf` 之外的字段一概不加 | 工具不读的字段只会让文件变脏 |

## 常见问题

**他训练的时候早读过这些书了，还有意义吗？**
有。"记得内容"和"有观点"是两件事。前提是：正文只能从库里取、笔记必须是他自己的位置、并且允许他说"我不同意"。
详见 [产品理念.md](产品理念.md) 里《动物庄园》那段。

**他抽到不想读的怎么办？**
弃读是合法结果，`finish_reading` 传 `abandoned: true` 就行。技能里明确写了"读不进去可以不读"。

**他怎么老说好话？**
这是最该警惕的一种"跑偏"。技能里有两条对策：每次读完**至少留下一处不认同或没被打动的地方**；
以及把"和你一起读"和"喜欢这一篇"分开算。如果翻十条笔记全是正面评价，那是他在配合你。

**我想改包名 / 改界面怎么办？**
包名在 `reading_room/src/main.ts` 和 `reading_room/manifest.json` 两处，改完要重新打包（见 `reading_room/如何重新打包.md`）。
只改界面的话，工具包不用动。

**支持别的宿主吗？**
只测过 Operit。工具包是普通 JS，主体逻辑（掷骰子、索引、笔记）跟宿主无关；
侧边栏用的是 Operit 的 Compose DSL，换宿主得重写那一层。

## 仓库里有什么

```
reading_ritual/
├── reading_ritual.ts    源码：13 个工具（顶部 METADATA 声明接口）
└── reading_ritual.js    编译好的成品，直接导入就能用
reading_room/
├── src/main.ts          注册侧边栏入口
├── src/ui/...ui.ts      界面
├── manifest.json        包声明
└── reading_room.toolpkg 编译好的成品
skill/ReadingRitual/     他的阅读规程：SKILL.md + 4 份 references
示例/                    三份可直接用的原子文件
入库说明.md              书库规格书（给助手看的）
产品理念.md              这个活动想做的事
```

**这个仓库不含任何书库正文。** 想读什么，请自备公版文本：

- 中文古籍：[维基文库](https://zh.wikisource.org/)
- 英文经典：[Project Gutenberg](https://www.gutenberg.org/)
- 注意：**仍在版权期内的作品不要往里放**（不同国家保护期不一样，比如《动物庄园》在英国、欧盟已过期，在美国要到 2041 年）。
